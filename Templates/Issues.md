# Issue description

```markdown
# Summary
Detailed description of the issue

# Tasks
- [ ] Update / add tests
- [ ] Implement feature
- [ ] Update documentation

# Proposed solution (optional)
Outline a possible implementation.

# Alternatives considered (optional)
Any existing solutions or approaches you considered.

# Additional context / notes (optional)
Any other information, mockups, links or references.
```
# Sub Issues
Once the description is complete, add any corresponding sub-issues as needed.

# Issue assignment
All issues require a type. Keeping the type in mind helps organize and prioritize work. An issue can be one of the following:

```markdown
Bug -> Use this type if the objective is to fix an existing bug. Make sure the bug is clearly and properly explained in the description.

Feture -> Use this type if something new needs to be added that does not currently exist in the software.

Task -> Use this type for general work that is needed but is not a bug or a new feature. For example: documentation updates, refactoring, testing, or research tasks.
```
